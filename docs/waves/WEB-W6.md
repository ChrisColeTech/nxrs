## Plan

### 1. Hot/cold split (live)

- **Hot set:** one native run with `NXRS_FNPROF=<file>` (`py scripts/play.py agsob --env NXGFX_GPU=1 --env
  NXRS_FNPROF=...`), through beach gameplay. The recorder writes guest addresses at the native module base; the web
  build translates its modules at `WEB_FIRST_BASE`, so the build maps them by module offset to the web names
  (`f_<addr>`).
- **Build input:** the recording lives in the web data folder as `<name>_data/hotset.txt` (beside
  `bootset.rec.json`, the same kind of thing); regenerated by the run above and copied there. No recording: no split
  (one module, as today).
- **Split:** the link keeps names (`--profiling-funcs`), then `wasm-split` moves every guest function outside the
  hot set into `game.cold.wasm`; everything else (runtime, libc, Rust, the hot guest functions) stays in `game.wasm`.
  Only guest functions move, so a cold call can only come from a guest thread (a pthread), never the page's thread.
- **Load:** Emscripten's `SPLIT_MODULE` loader (placeholders through a proxy on the import object) with our own
  `loadSplitModule` (a `--pre-js`): a cold call on a thread that has no cold instance yet blocks on a synchronous
  fetch + compile of `game.cold.wasm` and continues (waits, never traps). The page starts fetching the cold module in
  the background after the hot one so that fetch is a cache hit.
- **Names:** stripped in the shipped modules; `game.symbols` (wasm-split's symbol maps) kept next to the build.

### 2. Optimization

`wasm-opt` (emsdk's binaryen) on the linked module before the split; levels tried and reported with size and time:
none (today), `-O1`, `-O2`. The default is the level that keeps the link within a few minutes.

### 3. Compressed serving

- Measure gzip/brotli ratios of `game.wasm`, `game.cold.wasm`, RomFS and the shader library.
- Code: precompressed at build time (`game.wasm.gz` etc.), served with `Content-Encoding` when the browser accepts
  it and the request is not a range; both the launcher server (`web_reply.rs`) and `dev_server.py`. Range requests
  always get the identity bytes, so W3's exact-206 checks are unchanged.
- Data: the choice (per-file, compressed extents, or identity) made from the measured ratios, and recorded here.
- Caching: `no-store` today makes every launch download the whole module again; host files and modules get
  revalidation (`ETag` + `no-cache`) so a warm launch is 304s.

### 4. Lazy shader packs

The library (`<data>/shaders/spv/<hex>.spv|.json`, 53,109 modules, 106k files, 3.4 GB) is fetched today with two
synchronous requests per module at first use. The build writes `shaders.pack` (each module's spv + json as one
compressed entry, the recorded used set first) and `shaders.idx` (key -> offset, length); the engine reads entries by
range through the I/O worker (OPFS-cached, boot-set prefetch for the used set), so first use is a few range
requests and a warm launch none.

### 5. Fallback font

The web build stops copying the build machine's Windows font: the engine embeds the repo's OFL `Hind-Regular.ttf` as
the web fallback, and `LICENSES/hind-ofl.txt` is written into the build folder. A `fonts/fallback.ttf` left by an
older build is removed.

### 6. Per-worktree Emscripten cache

`EM_CACHE=<worktree>\target\emcache` in `web.ps1` and in `cc.rs` (every emcc the CLI runs), so parallel worktrees do
not clear each other's cache through the shared emsdk junction.

- nnMain is later cold (7.6 vs 4.7 s) because the boot set (838.5 MiB, now 413 MiB of extents) is prefetched and inflated
  first (10.4 s); the game then reads 900 MiB from the cache with no demand fetch, and the title comes earlier.
- **Warm launch still downloads the module** (112 MB): the ETag / `no-cache` answers are in both servers and the
  launcher's are tested (304 on `If-None-Match`), but Chrome sent no revalidation for `game.wasm`; not diagnosed (the
  HTTP cache may not keep a 107 MB entry, or Emscripten's fetch bypasses it).
- **Split: blocker.** With the split module the engine reached nnMain and `WindowInitialize`, then nothing for 74 s,
  no request for `game.cold.wasm`, and the tab reloaded at ~87 s. The first split build had failed earlier on every
  thread (`wasmBinaryFile` undefined in pthreads; fixed in `split.js`); this second failure is not diagnosed. The
  split is therefore opt-in (`NXRS_WEB_SPLIT=1`); the default build is one module. Next step: the stack of the stalled
  threads (as W4b did with `game.symbols`) and whether the placeholder path runs at all in a pthread.
- Lazy shader packs: not done (346 shader requests before and after). W7's imported shaders land in the same
  `<data>\shaders` library, so a pack built from it includes them.
