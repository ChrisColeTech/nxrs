## Built

**Implemented a bounded missing-evidence discriminator; no causal rendering correction established.** The retained
data narrows the historical gap to depth/coverage versus colour production before final composition, but cannot
identify a first incorrect instruction or certify the same intermediate state on current source.

`exec.rs` retains the actual colour/depth views supplied to `vkCmdBeginRendering`, then resolves those exact views
at the existing pass-end boundary. It refuses to substitute a registered image for an unknown/dummy/stand-in view.
The supported raw capture is intentionally narrow: verified single-sample, single-level, single-layer 2D views;
D32 float depth and a small explicit uncompressed colour-format set. Unsupported views produce unknown identity /
zero bytes-per-pixel and cannot schedule a readback. Alias ownership is followed with a finite bound and must
resolve to the same actual image. Colour and depth are distinguished by aspect; slot 8 denotes depth.

`render_chain.rs` joins the current sampled/storage image-view metadata to the latest retained matching attachment
observation by backing owner, actual VkImage, aspect, extent and raw image format. Different view handles over the
same image can join; changed backing/owner/frame/aspect cannot. The owner's GPU-write sequence is retained: a
change reports `ChangedSince`, rather than presenting the old pixels as current. Consumer entries include exact
dump frame/submission/pass, selected shader key/stage and descriptor binding. The metadata comes from `stage_set`
after the actual `tex_view` resolution; the existing pass-dump mode disables set/texture-part caching, so cache hits
cannot bypass this observation. Bindings are not claimed to prove shader execution or writes.

### Diagnostic controls and bounds

- Off unless `NXGFX_RENDER_CHAIN=1`, and active only inside an existing pass-dump frame.
- Require `NXGFX_CHAIN_EXTENTS=WxH[,WxH...]`, at most four positive extents, each dimension <=16384. Invalid
  configuration is refused explicitly. This filters the small scene/depth/upscale chain rather than dumping all
  material textures.
- Optional `NXGFX_CHAIN_PASSES=p[,p...]`, at most 16 pass numbers. Empty means metadata only. Selected passes
  capture the verified supported colour/depth images as tightly packed raw `.bin`, preserving HDR/depth values.
- One dump frame per process; 16,384 metadata events; 256 FIFO attachment observations with eviction counts;
  at most 16 readback attempts and **64 MiB total requested payload**, reserved with checked arithmetic before any
  allocation or copy. Allocation failures conservatively consume their reservation. Another frame cannot reset
  the budget while callbacks are pending. Nine view handles per queue are the added queue-held state.
- Output names include frame, submission serial, pass, attachment slot, actual image, dimensions and Vulkan format.
  `Recorded` means scheduled only. A separate completion/file-write message is required; allocation/output errors
  are explicit. `NotSelected` and `BudgetOrExtent` are not successful pixel observations.
- Raw copies are outside rendering with existing full barriers. Their buffers belong to that exact `Sub` via
  `sub.transient`; its completion callback consumes bytes before transient retirement. No guest destination pointer,
  synchronous readback wait or fake completion signal is introduced. DV-01 code is unchanged.

Use `NXGFX_DUMP_PNG=0` and unset `NXGFX_DUMP_TEX` for the proposed bounded run: the new limits govern this diagnostic,
not the independent legacy PNG/texture-dump machinery. This wave did not execute any of the new GPU copy paths.
