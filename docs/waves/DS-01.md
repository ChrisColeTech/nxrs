hardware equivalence.** `kernels.rs::Job::args` now supplies 16 instead of 8 to the existing scalar

correction; the GLSL arithmetic already implements ordered FMA plus the supplied packing interval.
Consequently the GLSL edits are contract comments and the compiled SPIR-V identities are unchanged.

`reference.rs` now defaults to a packed-word helper oracle: low then high halves of eight A/B words,
starting from half C, one final half conversion. Convolution chains invoke it per 16-channel block;
resampler stage one invokes it once, stage two twice with the first rounded output as the second C.

no caller-selected rounding integer in the default CPU oracle. Expected adversarial bits are literal
dyadic derivations, not values obtained from the native GLSL or by feeding its output back as expected.

## Tests written

**Compiled, not executed.** Five new CPU tests in the absolute `contract_tests.rs` path above:

- `helper_midpoint_ties_signs_and_subnormal_products`: k=7/8 carry, positive/negative midpoint ties
  (even and odd mantissas), two below-half-minimum products combining to a half subnormal,
  signed underflow zero, largest subnormal to smallest normal, signed zero before ReLU.
- `helper_preserves_fp32_low_then_high_order_and_only_final_half_overflow`: 4096*4096 + 1 -
  4096*4096 must lose the unit in the FP32 left fold, while cancellation before the unit preserves it;
  65504 + 16 - 16 survives a midpoint at k=7, but a final 65520 overflows, for both signs.
- `up64_rounds_at_each_sixteen_boundary_and_carries_skip_as_c`: seven position pairs across the
  8/16/32/48/64 boundaries; each checks all 128 interior half outputs against fixed bits.
- `down16_tap_boundary_is_a_helper_boundary`: a tie split across two spatial taps must be lost,
  while k=7/8 within the second tap must carry.
- `every_native_matrix_job_selects_the_translated_contract`: every convolution/down/up/out/resample
  job passes interval 16 to the shader (fails immediately with the original interval 8).

Existing `tests.rs::hmma_eight_product_rounding_differs_from_current_translated_sixteen` is preserved
under its original name and sharpened: asserts corrected native job arguments, exact 0x3c00 versus
0x3c01 results and exactly 128 differing halves. With the pre-fix host argument this fails before the
oracle comparison; with the pre-fix GPU behavior the ignored GPU witness's new 0x3c01 assertion fails.
Rounding only at the end of all 64 products fails the cross-16 boundary cases. Rounding at eight fails
the within-16 cases, subnormal pair and transient-overflow examples. Wide/reassociated accumulation
fails the FP32 ordering counterexample. These are source-derived failure predictions, not executed
mutation-test results. Existing exhaustive finite half conversion and no-prefix-consumption tests remain.
